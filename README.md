# fcitx5-sekka

[fcitx5](https://github.com/fcitx/fcitx5) で [Sekka](https://github.com/kiyoka/sekka)
（石火）の入力方式を使うためのインプットメソッドアドオン。

変換エンジンは [libsekka](https://github.com/YuSabo90002/libsekka) を用いる。

[English version](README.en.md)

## 操作

モード切替のキーは無い。ローマ字入力の**大文字の位置**が変換の種類を決める。

| 打鍵 | 結果 |
|---|---|
| `kanji` + Ctrl-J | かんじ（ひらがなのまま） |
| `Kanji` + Ctrl-J | 漢字 |
| `kanJi` + Ctrl-J | 感じ（送り仮名付き） |
| `OkonaU` + Ctrl-J | 行う |
| `KAnji` + Ctrl-J | 漢字（Shift を押しすぎたときの救済。`Kanji` と同じ） |

先頭が大文字で、2つ目の大文字より前の部分（語幹）からかながまだ1文字もできていない
（子音だけ。単独の `n` も未確定の子音として扱う）とき、その2つ目の大文字は小文字として扱う。
SKK と同じ規則である（`SHIneru` は `Shineru`、`NAka` は `Naka`、`KAnJi` は `KanJi` と同じ）。
語幹にかなが1文字以上あれば従来どおり送り仮名になり（`AU` → 合う）、先頭が小文字の `kAnji` は
変わらない。打った文字は書き換えないので、選び直しの Ctrl-L やローマ字のままの確定では
`KAnji` が出る。設定項目は無い。

Ctrl-J は状態によって3つの意味を持つ。

- ローマ字バッファがあるとき: 変換して第1候補をプリエディットに置く（まだ確定しない）
- 第1候補が置かれている状態: 選び直しを開始する（ここで初めて候補ウィンドウが出る）
- 選び直し中: 次候補へ進む

選び直し中のキー割り当ては本家に準拠する。Ctrl-A 漢字 / Ctrl-U ひらがな / Ctrl-I・Ctrl-K
カタカナ / Ctrl-L 半角英字 / Ctrl-E 全角英字、Enter 確定、Esc 取消。候補のクリックでも
確定できる。数字キーによる番号選択は本家に無いため実装していない（候補に番号ラベルも
出さない）。

確定はトリガー以外の次のキーまで遅延する。これは「確定直後の選び直し」を、アプリへ
送った文字列を取り返さずに成立させるための設計である。

ローマ字の `wi` / `we` は 0.5.0 から「うぃ」「うぇ」になる（0.4.0 までは「ゐ」「ゑ」）。
「ゐ」「ゑ」は `yi`（または `wyi`）／`wye` で打つ。0.4.0 までに「ゐ」「ゑ」を含む読みで
学習・登録した語は、`wi` / `we` ではなくこの打ち方で読みを打つと候補に出る。

ローマ字を打っている途中で `/` を打つと、それまでのローマ字は変換せずにそのまま確定し、
`/` だけが入力中に残る。続けて打ったローマ字を Ctrl-J で変換すると、`/` は消えて後ろだけが
変換される（`Linux/Nihongo` + Ctrl-J → Linux日本語）。Ctrl-J 以外のキーで確定すると、`/` は
文字として出る（`and/or` + 空白 → and/or）。ローマ字を打っていないときの `/` は、これまでどおり
そのまま出る。英字と日本語を区切るためのもので、設定項目は無い。

接頭辞・接尾辞は SKK と同じく `>` を付けて打つ。`cho>` を打って Ctrl-J を押すと、接頭辞の読み
「ちょう>」の候補（第1候補「超」）が出る。続けて次の語のローマ字を打つと「超」が確定するので、
後ろの語はもう一度 Ctrl-J で変換する（接頭辞と後ろの語は2回の変換に分ける）。接尾辞は、変換した語が
表示されているときに `>` を打つ。`nihon` Ctrl-J で「日本」を出してから `>teki` を打つと、`>` を
打った時点で「日本」が確定し、Ctrl-J で接尾辞の読み「>てき」の候補（第1候補「的」）が出る
（日本的）。Ctrl-J をくり返すと、接頭辞・接尾辞の候補を順に替える。Ctrl-J を押さなければ、`>` は
これまでどおり文字のまま確定する（`a>b` + 空白 → a>b）。全角の「＞」は印にならない。送り仮名付きの
接尾辞と、Ctrl-R での接頭辞・接尾辞の登録には対応していない。

Ctrl-J を押してから30秒の間は、ローマ字を打つたびに、いま Ctrl-J を押したら出る第1候補が
入力パネルの上の行に `[日本語]` の形で出る（`Nihongo` → [日本語]、`nihongo` → [にほんご]）。
第1候補の表示中と選び直し中は出ない。30秒は Ctrl-J を押すたびに戻る。30秒たつか、Ctrl-G を
押すか、フォーカスが移ると消え、次に Ctrl-J を押すまで出ない。Ctrl-G のほかの働き（ローマ字を
そのまま確定する、選び直しを取り消す）は変わらない。設定項目は無い。

変換中（第1候補の表示中・選び直し中）に Ctrl-R を押すと、単語登録に入る。読みは打ったローマ字を
かなにしたもので、アプリの入力位置に出る。登録する単語は Sekka 自身の変換（ローマ字入力・Ctrl-J・
選び直し）で組み立て、入力パネルの上の行に出る。組み立てている途中でまた Ctrl-R を押すと、
その語の登録に入れる（段数に制限は無い）。Enter を押すと（読み, 単語）がユーザー辞書に入り、
単語がアプリへ確定する。登録した語は、次にその読みを変換したときの第1候補になる。Esc（または
Ctrl-G）で取り消すと Ctrl-R を押す直前の状態へ戻り、フォーカスが移ると何も出さずに終わる。
送り仮名付きの変換では Ctrl-R は何もしない。

登録する単語の中では、← と → でカーソルを1文字ずつ、Home と End で先頭と末尾へ動かせる（テンキーの
同じキーも使える）。打ったかなや変換の結果はカーソルの位置に入り、BackSpace はカーソルの前の
1文字を、Delete はカーソルの後ろの1文字を消す。ローマ字の打ちかけや変換の表示・選び直しの間は、
これらのカーソルキーは何もしない（何も確定しない）。登録していないときのこれらのキーは、これまで
どおりアプリへ渡る。

Sekka が有効な間、Alt を押したまま印字できるキーを打つと、Alt を外した文字として確定する
（エディタのキー割り当てには届かない）。プリエディット・第1候補・選び直しの候補が残っていれば、
その末尾に連結して確定する。Enter・Esc・BackSpace・Tab・矢印など文字にできないキーと、
Ctrl や Super が重なった Alt は、これまでどおりアプリへ転送する。

## 依存

- fcitx5 5.1.13 以降（辞書を新しい `StandardPaths` API で探すため。`FCITX_ADDON_FACTORY_V2` にも 5.1.12 以降が要る。Ubuntu 24.04 の 5.1.2 では足りない）
- libsekka（pkg-config の `sekka`）
- CMake 3.13 以降、C++20 コンパイラ
- gettext
- GoogleTest（`-DENABLE_TEST=ON` のときのみ）
- 通知（任意）: fcitx5 の notifications アドオン。辞書の読み込みに失敗したときの通知に使う

## ビルド

libsekka を先にインストールする。libsekka のリポジトリ（チェックアウト）の根で次を打つ。

```sh
cargo cinstall --release --prefix=/usr --libdir=lib
```

続いてアドオンをビルドする。fcitx5-sekka のリポジトリ（チェックアウト）の根で次を打つ。

```sh
cmake -S . -B build -DENABLE_TEST=ON
cmake --build build
(cd build && ctest)
sudo cmake --install build
```

## マスター辞書

既定では辞書を生成しない。`-DSEKKA_BUILD_DICT=ON` を明示したときだけ、SKK-JISYO.L
（固定コミット＋SHA256 で検証）を取得して `master-dict.db` を生成し、
`${FCITX_INSTALL_PKGDATADIR}/sekka/` へ 0444 でインストールする。

```sh
cmake -S . -B build -DSEKKA_BUILD_DICT=ON -DSEKKA_DICT_TOOL=/path/to/sekka-dict-tool
cmake --build build
```

オフライン環境では `-DSEKKA_SKKJISYO_SOURCE=<取得済みSKK-JISYO.Lのパス>` を指定する。

生成物は 0444 である必要がある。マスター辞書は mmap されるため、実行ユーザーから
書き込み可能なパスに置かれているとアドオンがロードを拒否する（mmap 中の書き換えによる
SIGBUS を避けるため）。

## 辞書の探索

設定の「辞書パス」が空のとき（既定）、Sekka は `sekka/master-dict.db` を fcitx5 のデータ
ディレクトリから次の順に探し、最初に読み込めた1つを使う。

1. `$XDG_DATA_HOME/fcitx5/`（未設定なら `~/.local/share/fcitx5/`）
2. `$XDG_DATA_DIRS` に並ぶ各ディレクトリの `fcitx5/`（先頭から順に）
3. fcitx5 自身のインストール先のデータディレクトリ（例: `/usr/share/fcitx5/`）

- 自分で用意した辞書を使うときは `$XDG_DATA_HOME/fcitx5/sekka/master-dict.db` に置く。
  システムの辞書より優先される。
- 辞書ファイルは実行ユーザーから書き込めない状態（`sekka-dict-tool` の出力どおり 0444）で
  置く。書き込み可能・壊れている・読めない辞書は、理由を通知したうえで飛ばし、次の候補を
  試す（書き込み可能な辞書を拒否する理由は「マスター辞書」の節の mmap と SIGBUS の説明を
  参照）。
- どこにも見つからないときは、探した場所を並べた通知が出る（多いときは先頭3件と残りの
  件数）。辞書が無くても入力は止まらず、ひらがなのまま確定できる。
- 「辞書パス」にパスを書くと、探索せずにそのパスだけを使う。そのパスが読めなくても、
  探索で見つかる別の辞書へはフォールバックしない（打ち間違いに気づけるようにするため）。
- 0.1.0 の既定値 `/usr/share/fcitx5/sekka/master-dict.db` が設定に残っている場合は、
  空と同じに扱って探索する。設定ファイルは書き換えない。
- NixOS など `/usr/share` を持たない環境でも、fcitx5-sekka を入れた prefix の `share` が
  `XDG_DATA_DIRS` に載っていれば設定は要らない。

## 設定

fcitx5 の設定ツール（`fcitx5-configtool`）から変更できる。

| 項目 | 既定値 |
|---|---|
| 辞書パス | 空（自動で探す。「辞書の探索」を参照） |
| ユーザー辞書パス | 空（`$XDG_DATA_HOME/fcitx5/sekka/user-dict.db`、未設定なら `~/.local/share/fcitx5/sekka/user-dict.db`） |
| 変換キー | `Control+j` |

辞書パスの変更は fcitx5 を再起動せずに反映される。空に戻すと探索に切り替わる。
